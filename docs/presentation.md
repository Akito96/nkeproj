# Презентация для защиты практики (12 слайдов)
**Тема:** Веб-приложение для автоматизации работы ремонтной мастерской «РемМастер»  
**Рекомендуемый тайминг выступления:** 7–8 минут (~35–40 секунд на слайд)

---

## Слайд 1. Титульный слайд
- **Заголовок:** Разработка веб-приложения «Ремонтная мастерская»
- **Подзаголовок:** Информационная система учёта заявок, склада запчастей и аналитики сервисного центра
- **На слайде:** ФИО студента, группа, руководитель практики, год, технологический стек (FastAPI · PostgreSQL · SQLAlchemy 2.0 · Vanilla JS).
- **Речь докладчика:** «Добрый день, уважаемая комиссия! Представляю результаты практики — веб-приложение «РемМастер» для автоматизации бизнес-процессов сервисного центра по ремонту электроники».

---

## Слайд 2. Актуальность и проблематика
- **Заголовок:** Проблемы сервисных центров и цель проекта
- **Тезисы:**
  - Учёт в Excel/мессенджерах → потеря истории ремонтов, «зависшие» заказы, пересортица на складе.
  - Информационный вакуум для клиента → 30–40% звонков в приёмку с вопросом «Когда готово?».
  - Коммерческие CRM (RemOnline, Livesklad, 1С) дороги, привязаны к облаку и не дают клиенту полноценного кабинета.
  - **Цель:** создать self-hosted веб-систему для 3 ролей (`client`, `master`, `admin`) с прозрачным жизненным циклом заявки и точным складским учётом.
- **Визуал:** 3 иконки проблем → стрелка к решению.

---

## Слайд 3. Функциональные требования и ролевая модель
- **Заголовок:** Роли пользователей и ключевой функционал
- **Тезисы (3 колонки):**
  - **Клиент (`client`):** регистрация/вход, подача заявки с фото (до 5 шт.), личный кабинет, таймлайн статусов и сметы.
  - **Мастер (`master`):** список назначенных заявок, диагностика, перевод статусов по цепочке, списание запчастей, комментарии.
  - **Администратор (`admin`):** назначение мастеров, CRUD пользователей/услуг/склада, Kanban-доска, статистика по периодам.
- **Визуал:** Схема взаимодействия трёх ролей вокруг единого REST API.

---

## Слайд 4. Архитектура и стек технологий
- **Заголовок:** Архитектура системы и выбор технологий
- **Тезисы:**
  - **Backend:** Python 3.13, FastAPI, Pydantic v2 (валидация и ошибки на русском), SQLAlchemy 2.0, Alembic, PostgreSQL 16 (Docker).
  - **Безопасность:** JWT (`HS256`) + `bcrypt` (12 раундов) + ролевой гард `require_role`.
  - **Frontend:** Vanilla HTML5/CSS3/JS (mobile-first, без тяжёлых фреймворков), единый модуль `js/api.js`, **Chart.js** и **SortableJS**.
  - **Принцип:** роутеры только маршрутизируют запросы, 100% бизнес-логики — в слое `services/`.
- **Визуал:** Слоистая диаграмма `Browser (Vanilla JS) → FastAPI Routers → Services → SQLAlchemy ORM → PostgreSQL`.

---

## Слайд 5. Проектирование базы данных (3НФ)
- **Заголовок:** Схема базы данных (9 таблиц, 3НФ)
- **Тезисы:**
  - Центральная сущность `requests` связана с `users` (клиент и мастер) и `services`.
  - Аудит и вложения вынесены в отдельные таблицы: `status_history`, `master_comments`, `request_photos`.
  - Складской контур: `parts`, связующая `request_parts` (`M:N` с фиксацией исторической цены `unit_price`) и журнал `stock_movements`.
  - Все изменения схемы управляются миграциями **Alembic**.
- **Визуал:** ER-диаграмма из раздела 3 отчёта.

---

## Слайд 6. Ключевые механизмы бэкенда
- **Заголовок:** Цепочка статусов и транзакционное списание склада
- **Тезисы:**
  - **Конечный автомат статусов:** `Принята → В диагностике → В ремонте → Готова к выдаче → Выдана`. Перескок или откат блокируется (`400 Bad Request`), каждый шаг пишется в `status_history`.
  - **Атомарность склада (`SELECT FOR UPDATE`):** блокировка строки запчасти в БД, запрет отрицательного остатка, автоматический откат всей транзакции при нехватке детали, флаг низкого остатка `is_low_stock`.
  - **Безопасная загрузка фото:** проверка MIME/расширения (`JPG/PNG/WEBP`), размера (> 0 байт и ≤ 5 МБ), до 5 файлов, генерация UUID-имён.
- **Визуал:** Схема цепочки из 5 статусов + схема транзакции списания.

## Слайд 7. Публичная часть и подача заявки
- **Заголовок:** Главная страница, каталог услуг и форма заявки
- **Тезисы:**
  - Единая адаптивная вёрстка (от 360px до 1920px), мятная цветовая тема, типографика `Montserrat` + `Manrope`.
  - Каталог услуг (`services.html`): поиск, фильтрация по категориям, пагинация из БД.
  - Форма заявки (`create-order.html`): предвыбор услуги, клиентская валидация, превью до 5 фотографий с проверкой формата/размера и удалением до отправки.
- **Визуал:** Скриншоты главной страницы и формы заявки с превью фото.

---

## Слайд 8. Личный кабинет клиента и рабочее место мастера
- **Заголовок:** Прозрачность для клиента и рабочее место мастера
- **Тезисы:**
  - **Кабинет клиента (`client.html`):** фильтр заявок по статусам, 5-шаговый прогресс-бар, вертикальный таймлайн `status_history`, смета и публичные комментарии.
  - **Рабочее место мастера (`master.html`):** только назначенные заявки, смена статуса строго по разрешённым переходам, диагностика, подбор запчастей со склада с контролем остатков, внутренние и клиентские комментарии.
- **Визуал:** Два скриншота рядом: таймлайн клиента + карточка заявки у мастера.

---

## Слайд 9. Админ-панель и Kanban-доска (SortableJS)
- **Заголовок:** Администрирование и интерактивная Kanban-доска
- **Тезисы:**
  - **Админ-панель (`admin.html`):** 4 вкладки (Заявки, Пользователи, Услуги, Склад), адаптивные таблицы (`@container`), нативные модальные `<dialog>` для CRUD и складских движений.
  - **Kanban-доска (`kanban.html`, SortableJS):** 5 колонок по статусам, фильтрация по мастеру и поиску; перетаскивание отправляет `PATCH /api/master/orders/{id}/status`.
  - **Откат при ошибке:** при недопустимом переходе API возвращает `400`, карточка автоматически возвращается на прежнюю позицию с toast-уведомлением.
- **Визуал:** Скриншот Kanban-доски с 5 колонками.

## Слайд 10. Аналитика и статистика (Chart.js)
- **Заголовок:** Статистика работы мастерской
- **Тезисы:**
  - Выделенный эндпоинт `GET /api/admin/stats` с фильтрацией по периоду (`7 / 30 / 90 дней / Всё время` и ручной выбор дат).
  - 4 KPI-метрики (выручка, средний чек, всего заявок, в работе/выдано).
  - 4 интерактивных графика **Chart.js**:
    1. Динамика выручки и заявок по дням (Line);
    2. Распределение по статусам (Doughnut);
    3. Выручка по типам устройств (Bar);
    4. Загрузка и выручка мастеров (Horizontal Bar).
- **Визуал:** Скриншот страницы `stats.html` с 4 графиками.

## Слайд 11. Тестирование и контроль качества
- **Заголовок:** Тест-план и автоматизированное тестирование
- **Тезисы:**
  - Составлен тест-план и 16 детальных тест-кейсов (`TC-01`–`TC-16`).
  - Реализовано **27 автотестов** на `pytest` + `TestClient` (`httpx`) с отдельной изолированной тестовой БД и временным каталогом `uploads`.

  - Статический контроль: `ruff` — 0 ошибок, `mypy` — 0 ошибок (35 файлов), `pytest` — **27/27 passed**.
- **Визуал:** Скриншот успешного вывода `pytest -v` и сводная таблица результатов.
